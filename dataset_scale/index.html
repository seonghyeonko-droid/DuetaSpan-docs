Each dialogue is stored as three files: one interleaved stereo (L=user, R=agent) plus the two per-speaker monos it was built from. The stereo therefore duplicates content already on disk — unique content is ≈1.31 TB, and the 12,573-hour figure counts it once. Converting dsp_export from WAV to FLAC would reclaim ≈215 G.

Counting key is part|id, not the filename. dsp_export reuses the same slot id across parts, so de-duplicating on filename alone collapses 50,455 dialogues to 628.

2. Augmentation spec

Acoustic variation is produced only in the augmentation layer. Nothing is baked into the source audio. Each dialogue stores user_variants[5,8,T] — one hard-clean plus four augmented realizations — and training draws one at random on every access, so the same dialogue is heard differently each epoch.

operationtracklabeled overlap span
echo (agent leak)p = 0.3unchanged
reverb / RIRp = 0.3independently redrawn — the one differentiator
noisep = 0.3unchanged
gainp = 0.5, uniform −24…+15 dBsmall offset, within ±6 dB
no gate fires → output is bit-identical to inputverified
Why operation-level, not re-running the pipeline on the span. Slicing the span and passing it through AcousticAug again would necessarily redraw noise and echo, so the noise floor would jump at the boundary and the room would stop being the only difference. Instead the track pipeline runs once (echo → reverb → noise → gain), and only the RIR difference is cross-faded into the span (20 ms), with the gain offset applied as a scalar. Unit tests assert the echo and noise logs are character-for-character identical inside and outside the span.

Label coverage: 47,227 dialogues (side_to_other 40,883 / background 6,349) carry a verified overlap span. Labels were recovered by joining the per-turn marker — which survives in the generation records but was dropped when export wrote the per-dialogue text JSON — back to timeline wall-clock. Alignment was verified, never assumed: dialogues whose record and export snapshot disagreed were skipped rather than guessed.

Known defect — background is currently mis-built. In the existing corpus a background line was emitted as an ordinary turn on the user track, so it sits in a silent gap and the agent waits for it to finish — teaching exactly the wrong behaviour — and it was synthesized with the user's own voice. Full-scan audit in progress. The correct construction, being implemented now, injects a rendered utterance borrowed from another dialogue at a random time with its own RIR: a different voice comes for free, and occupying no turn slot makes interrupting the conversation structurally impossible.
Known defect — channel value mismatch. textgen_v2 writes channel: "side" while the assembler only recognises ("side_to_other", "background"), so 205,448 marker turns never received a channel in the timeline. Recovering labels from the generation records worked around this; the generator itself is still affected.

3. Data rules added 2026-07-29

#rule
17-c2Overlap RIR is an independent draw from the same pool — not a far-field or long-reverb spec. "Slightly different" is the target; landing on something similar is acceptable.
25background uses a different voice from the user; side_to_other uses the same voice. Both get their own room draw.
26Background speech is a clip borrowed from another generated dialogue, not from the voice-reference bank (bank clips are fixed lines and would repeat the same sentence everywhere).
28Context DB is mandatory in every dialogue, not conditional on kind. A dialogue without one is not training data. Retrieval must go through the router with the Context DB always in scope — no source == "mem" gate, no lexical shortcut.
